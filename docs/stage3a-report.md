# Этап 3a — сцена и данные

Подэтап без стилизации: задача была доказать, что данные реально текут и муха
реагирует на реальные события снимка, а не на заглушки.

## Что собрано

```
web/
  index.html
  vite.config.ts        плагин отдаёт ../snapshots как /api (в проде это nginx)
  src/
    types.ts            контракт снимка, один в один с worker/snapshot.py
    api.ts              опрос раз в секунду, отбрасывание несвежих ответов
    fly.ts              процедурная low-poly муха
    phone.ts            телефон + canvas-текстура с NearestFilter
    motion.ts           усиление движения из моторных частот
    scene.ts            сцена, OrbitControls, покадровая поза
    panels.ts           категории, нейроактивность, комната с интересами
    main.ts             сборка, параметризация по комнате
    styles/base.css     служебная разметка + сетка с брейкпоинтами
```

## Разбор референса

Открыл `stonkfly-three.vercel.app/#watch` и вытащил его CSS. Три брейкпоинта:
**1120 / 780 / 360**. Принцип, который повторён:

| Ширина | Что делает референс |
|---|---|
| десктоп | `grid-template-areas`, колонки `minmax(0,1.15fr) minmax(430px,1fr)` |
| ≤1120 | колонки ужимаются, строка статистики 4 колонки → 2×2 |
| **≤780** | **`grid` → `flex column`**, блоки на всю ширину |
| ≤360 | мелкая подгонка кеглей |

У нас сетка 2×2 по вашей композиции (`main-ref-compos-final.png`):
`"stage categories" / "activity room"`. На 1120 колонки ужимаются и метрики
активности встают в одну колонку, на 780 — переход в поток. Проверено
рендером в iframe шириной 390 и 900: перестроение, а не сжатие.

## Муха

Геометрия своя. Из клонов взят **метод**, не файл: тело — икосаэдры низкой
детализации с плоским затенением, лапы — цепочки цилиндров с вложенными
группами-суставами, крылья — буферная геометрия с жилками-трубками. Готовых
моделей и ассетов со стороны нет.

Иерархия лапы (`root → coxa → femur → tip`) сделана так, чтобы анимация
сводилась к вращению двух суставов — это понадобится для жеста касания.

## Движение из активности

`motion.ts`. Предзаписанной анимации нет ни одной. Каждый кадр поза
пересчитывается из `motor_hz` и `turn_hz` снимка через два преобразования:

1. **Насыщающая кривая** `x/(x+k)` — сжимает частоту в 0..1 без обрезания.
   Пороги: 4 Гц для моторики, 10 Гц для поворота, по реальному размаху из
   прогонов этапа 1.
2. **Огибающая** с атакой 100 мс и спадом 700 мс (поворот сглаживается за
   200 мс) — иначе при опросе раз в секунду движение рваное.

Что к чему привязано:

| Данные снимка | Что двигают |
|---|---|
| `motor_hz` (MN9/DNp09) | размах и частота взмаха крыльев, качание, дрожь лап |
| `turn_hz` (правые − левые DNa02) | поворот головы и крен корпуса |
| рост `selection.selected` | лапа тянется к экрану |

Жест касания запускается **только ростом числа занятых слотов в снимке**, а не
таймером на клиенте. Лапа приходит в район экрана; попадание в конкретную
плитку не вычисляется и не подгоняется.

## Экран телефона

Canvas 180×320 с `NearestFilter` и выключенными мипмапами — пиксельность
получается из низкого разрешения текстуры, а не из фильтра поверх. HTML-текста
на экране нет вообще: иначе он не жил бы в 3D и не поворачивался бы вместе с
устройством.

## Синхронизация событий

Проверено на живом воркере:

- **Галочки** ставятся строго по `selection.selected`. Своей логики у клиента
  нет — `panels.ts` только читает массив.
- **Подсветка интереса** включается, когда интерес сыграл в уже выбранной
  категории: берём выбранные категории с `boosted: true`, смотрим пересечение
  их тегов с тегами интереса. Совпадения тега самого по себе недостаточно.
  На скриншоте видно: выбраны Супермаркеты и Лавка → горят «Фрукты»
  (теги `супермаркеты`, `лавка`), остальные интересы тусклые.
- **Смена месяца** обнуляет список и галочки — кольцо из четырёх месяцев
  прокрутилось за время проверки полностью.
- **Фаза** показывается из `phase`: «Нюхает категории» / «Занимает слоты» /
  «Выбор сделан».

## Панель активности

По референсу FlyTok (`some-activity/active-1.png`), все подписи по-русски:

- «Активность бокового рога» — крупное число в Гц, снизу размер пула
  (2 028 нейронов, берётся из `provenance`, не вшито);
- «Спайков за окно» — счётчик и длительность окна нейронного времени;
- «Частота разрядов» — осциллограмма с автомасштабом; границы подписываются
  фактические (например 41,6–48,1 Гц), а не от нуля: сигнал живёт в узкой
  полосе около 44 Гц, и шкала от нуля дала бы прямую линию;
- строка «По интересу: N · Сама: M».

Декоративных чисел нет: всё из полей снимка.

## Комнат может быть несколько

Клиент читает `/api/rooms.json`, и если комнат меньше двух — переключатель
скрыт (`hidden`), но разметка под него на месте. Комната живёт в адресе как
`?room=<id>`, снимок грузится по её идентификатору. Вторая комната = флаг в
конфиге воркера; фронтенд не трогается.
