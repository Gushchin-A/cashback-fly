# Этап 2 — воркер

Что сделано: `worker/main.py` (цикл и потоки), `worker/snapshot.py` (сборка и
атомарная запись), сохранение и восстановление состояния в
`neural/flybrain.py`, тесты в `tests/test_snapshot.py` и `tests/test_worker.py`.

## Архитектура

```
[один процесс]
  ├── проводка MaleCNS v1.0 — одна копия в памяти
  ├── поток комнаты 1 … N — независимые состояния, без барьера
  └── поток вещания — раз в секунду пишет snapshot_{room}.json атомарно
```

Число комнат берётся из `config/rooms.json` по флагу `enabled`. Потоки, пути
снимков и индекс строятся по этому списку, в коде числа комнат нет нигде.

Каждая комната — свой поток. Ядро вызывается через `ctypes`, который отпускает
GIL на время счёта, поэтому потоки считают действительно параллельно.
**Барьера между комнатами намеренно нет:** в Этапе 0 замер показал, что
синхронные пачки на M4 упираются в четыре производительных ядра и на пятом
потоке пропускная способность падает, а свободный ход распределяется ровно.

Зритель на расчёт не влияет. Снимки пишутся по таймеру независимо от того,
читает их кто-нибудь или нет. Тысяча зрителей — это тысяча чтений одного
статического файла; воркер считает ровно столько же, сколько при одном.

## Цикл комнаты

старт → накопление → фиксация слотов → пауза → следующий месяц в кольце → повтор

| Фаза | Что происходит | Окон |
|---|---|---|
| `accumulating` | 2 прохода по всем категориям, растут рейтинги | 34 |
| `revealing` | слоты занимаются по убыванию рейтинга, по одному за окно | 5 |
| `pause` | счёт остановлен, выбор показан | — |

**Темп.** На окно отводится `(cycle_seconds − pause_seconds) / окон`. Если
машина считает быстрее — воркер ждёт и держит заявленный цикл. Если медленнее
— не ждёт вовсе, и цикл просто длиннее. На слабом VPS это честнее, чем делать
вид, что уложились.

Замер на M4: цикл **25 с** при бюджете 26 (`cycle_seconds = 30`, пауза 4).

## Снимки

Путь `snapshots/rooms/{id}/snapshot.json` → nginx отдаёт как
`/api/rooms/{id}/snapshot.json`. **Идентификатор комнаты в пути всегда**,
даже когда комната одна.

Рядом `snapshots/rooms.json` — индекс: какие комнаты существуют, где их
снимки, провенанс расчёта и дисклеймер. Клиент читает его и сам решает,
показывать переключатель или нет; конфиг воркера ему знать не нужно.

Размер снимка — 8 КБ. В нём: комната с интересами и тегами, месяц, все 17
офферов с процентом, тегами, признаком усиления и текущим рейтингом,
состояние выбора, фаза и прогресс, активность (96 нейронов с их разрядами,
история решающего пула, моторные показания для 3D), счётчики спайков,
нейронное время, число закрытых циклов, аптайм, таймкод и порядковый номер.

### Атомарность

Запись идёт во временный файл **в том же каталоге**, затем `os.replace`.
Временный файл именно рядом: rename атомарен только внутри одной файловой
системы. Перед заменой — `fsync`, иначе переживший панику ядра файл может
оказаться пустым.

Проверено тестами, а не рассуждением:

- параллельно пишущий поток и четыре читающих — ни один не увидел
  незавершённый JSON;
- порядковый номер у читателя никогда не убывает;
- после 20 записей в каталоге ровно один файл, временных не остаётся;
- при сбое сериализации временный файл удаляется, целевой не появляется;
- временный файл создаётся в целевом каталоге (проверено подменой
  `os.replace`).

## Остановка и восстановление

По `SIGTERM` и `SIGINT` воркер досчитывает текущее окно, сохраняет состояние
каждой комнаты и пишет финальный снимок.

Состояние — это две вещи: нейронный чекпойнт (`brain.npz`, 6,4 МБ, механизм
stonkfly с проверкой провенанса) и ход цикла (`cycle.json`: месяц, расписание,
рейтинги, занятые слоты, курсор). Порядок записи важен: сначала мозг, потом
ход цикла. Если процесс умрёт между ними, при старте не найдётся ход цикла и
комната честно начнёт месяц заново, а не подхватит рассогласованный.

Восстановление отказывается от чекпойнта, если изменились `interest_gain`,
число проходов или слотов: старые рейтинги считались другими настройками, и
сравнивать их с новыми нельзя. Это не ошибка, а причина начать заново.

## Проверено

| Что | Как |
|---|---|
| Цикл закрывается, снимок полный | `--once`, все поля на месте, слоты уникальны и из этого месяца |
| Состояние переживает перезапуск | второй запуск пишет «состояние восстановлено» и закрывает **следующий** месяц |
| `SIGTERM` сохраняет состояние | сигнал живому процессу → код возврата 0, `brain.npz` и `cycle.json` на диске |
| N комнат из конфига | прогоны на 2 и 3 комнатах: ровно столько снимков, индекс совпадает |
| Кольцо месяцев | 4 месяца, обход по порядку и замыкание (`test_month_ring_closes_for_any_count`) |

Живой прогон на трёх комнатах: цикл 28 с против 25 у одной — параллельность
работает, и три комнаты укладываются в те же 30 секунд.

Всего тестов: **62** (31 быстрый + 31 на полном графе).

## Что осталось за рамками

- `cycle_seconds = 30` проверено для одной комнаты на M4. Для пяти комнат на
  вашем VPS значение надо будет подобрать по замеру — механизм темпа это
  переживёт без правок, он просто перестанет ждать.
- nginx-конфиг и Docker — Этап 4.

## Воспроизведение

```sh
export OPENBLAS_NUM_THREADS=1
.venv/bin/python -m worker.main --once      # один цикл и выход
.venv/bin/python -m worker.main             # вещание до Ctrl-C

.venv/bin/python -m pytest tests/ -q
FLY_FULL_TEST=1 .venv/bin/python -m pytest tests/ -q
```
